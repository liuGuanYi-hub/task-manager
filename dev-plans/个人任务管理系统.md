# 个人任务管理系统开发计划

## 项目概述
创建一个基于命令行的个人任务管理系统，帮助用户高效管理日常任务和项目。

## 技术栈
- **开发语言**: Python 3.8+
- **数据存储**: JSON/SQLite
- **可选扩展**: Web 界面 (Flask/FastAPI)

## 核心功能

### 第一阶段：基础功能
1. 任务 CRUD 操作（创建、查看、更新、删除）
2. 任务优先级设置（高/中/低）
3. 任务状态管理（待办/进行中/已完成）
4. 任务分类/标签系统

### 第二阶段：进阶功能
1. 任务截止日期和提醒
2. 任务搜索和过滤
3. 任务统计和报表
4. 数据导出功能

### 第三阶段：扩展功能
1. 重复任务支持
2. 子任务分解
3. 时间追踪
4. Web 界面或 GUI 界面

## 开发周期
- **总周期**: 4 周
- **每周目标**:
  - 第 1 周：项目架构 + 基础 CRUD
  - 第 2 周：任务管理和分类功能
  - 第 3 周：搜索统计和报表
  - 第 4 周：扩展功能和优化

本项目已经完成基础任务管理和 Web 扩展，当前实际状态如下：

- 当前测试基线：`python -m pytest tests/ -q`，20 个测试全部通过。

### 二、升级原则

1. 保留现有命令行入口和 Flask 页面，不做一次性重写。
2. 先稳定任务模型、查询规则和数据兼容，再增加看板和保存视图。
3. JSON 继续作为当前默认存储；只有当查询和关系复杂到 JSON 难以维护时，才引入 SQLite。
4. 参考 Plane 的项目/迭代/视图，参考 Focalboard 的卡片界面，参考 WeKan 的看板和状态流转；不直接复制大型项目代码。
5. 每个阶段都必须补测试，并保持原有 20 个测试通过。

### 三、分阶段开发计划

| 阶段 | 目标 | 主要内容 | 完成标准 |
|---|---|---|---|
| 阶段 0：语义校准 | 修正现有功能的业务含义 | 日历同时区分创建日期和截止日期；统一日期解析；确认提醒只针对未完成且临近截止的任务 | 日历、提醒、周报对同一任务的日期解释一致；新增日期边界测试 |
| 阶段 1：任务模型增强 | 为归档和项目化做基础 | 增加 `updated_at`、`completed_at`、`archived`；为 JSON 旧数据提供默认值；保留标签兼容；抽取统一查询/排序方法 | 旧 `tasks.json` 可正常读取；完成、归档、恢复可测试；原有 CLI/Web 不回归 |
| 阶段 2：显式项目与阶段 | 借鉴 Plane 的层级结构 | 增加轻量 `Project` 概念；任务通过 `project_id` 关联项目；保留无项目任务；先用“阶段”替代复杂 Cycles | 项目不再依赖标签生成；项目详情可查看进度；标签仍只承担分类职责 |
| 阶段 3：WeKan 式看板 | 增加直观的状态流转 | 新增 `/board`；按待办/进行中/已完成分列；支持表单提交或轻量 JavaScript 更新状态；移动端保持可用 | 看板和列表数据一致；状态更新后 JSON 持久化；至少覆盖三种状态流转测试 |
| 阶段 4：Focalboard/Plane 式保存视图 | 减少重复筛选操作 | 支持按项目、状态、优先级、标签、截止日期组合筛选；允许保存常用筛选视图 | “高优先级未完成”“本周到期”等视图可保存、读取和删除；查询结果稳定排序 |
| 阶段 5：可靠性与历史 | 避免误删并增强复盘 | 删除改为归档；增加恢复、归档列表、备份导出；补充导入校验和冲突处理 | 归档任务不出现在默认列表；可恢复；导入错误不会破坏现有数据 |
| 阶段 6：可选 SQLite/API | 为数据规模增长做准备 | 先定义存储接口，再实现 SQLiteStorage；保留 JSON 导入导出；按需要增加只读 REST API | JSON/SQLite 可切换；迁移可重复执行；API 与 CLI/Web 使用同一业务服务 |

### 四、推荐实施顺序

当前最应该先做阶段 0 和阶段 1，具体顺序为：

1. 修正日历使用 `created_at`/`due_date` 的语义，并补日期边界测试。
2. 增加归档字段和更新时间字段，确保旧 JSON 数据向后兼容。
3. 抽取统一的任务筛选、排序和统计服务，避免每个路由重复遍历任务。
4. 再增加显式项目模型，避免继续把标签当项目使用。
5. 最后实现看板和保存视图。

### 五、暂不纳入范围

- 多用户登录、角色权限和团队邀请。
- Redis、PostgreSQL、Kubernetes 和实时 WebSocket。
- AI 自动拆解任务、云端同步和复杂第三方集成。
- 一次性迁移到 React/Vue 或复制 Plane 的完整前端架构。

这些能力属于大型协作平台方向，当前阶段引入会增加部署、认证和数据迁移风险，不符合项目“本地可运行、功能可验证”的优先级。

### 六、主要风险与验收检查

- **标签到项目的迁移风险**：同一标签可能被当作分类，也可能被当作项目；迁移时保留标签，不自动删除或强制转换。
- **JSON 兼容风险**：新增字段必须使用 `data.get()` 默认值，不能让旧数据无法读取。
- **日期语义风险**：创建日期适合趋势统计，截止日期适合日历和提醒，两者不能混用。
- **删除风险**：归档、恢复和永久删除要分开，默认操作不应破坏历史数据。
- **回归风险**：每个阶段完成后运行 `python -m pytest tests/ -q`，并手动检查 CLI、任务列表、日历、项目和统计页面。
